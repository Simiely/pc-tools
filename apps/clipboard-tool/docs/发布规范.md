# 发布规范（Release Rules）

> 本规范定义 clipboard-tool 的**发版规则**：版本号、产物形态、打包、发布、部署全流程。
> 适用范围：本地服务版（bat）/ 平台版（tools-center）。

## 一、版本号规则

- 语义化版本 **`v主.次.补丁`**（如 v0.6.14），与 `CHANGELOG.md` 版本节一一对应
- `package.json version` 必须与 CHANGELOG 同步（v0.6.14 起执行，此前 0.5.1 脱节过）
- 发布时打 tag：`git tag v<版本>`，与 GitHub Release tag 一致
- **版本指纹**：server.mjs 启动日志打印 `clipboard v<版本> (<commit>)`，任何实例可追溯

## 二、交付形态与产物

| 形态 | 产物命名 | 内容 | 启动方式 |
|---|---|---|---|
| **exe 桌面版** | `clipboard-tool-v<版本>-exe.zip` | `Clipboard.exe`(单文件 PublishSingleFile,含 .NET 9 DLL + 嵌入 pdb) + 使用说明.md | 双击 `Clipboard.exe`（需 .NET 9 Desktop Runtime x64） |
| **本地服务版** | `clipboard-tool-v<版本>-bat.zip` | 程序(server.mjs+lib+public) + delivery + 使用说明 | 双击 `delivery/server/start-server.cmd` |
| **平台版** | `clipboard-tool-v<版本>-platform.zip` | 程序 + tool.json + 部署说明 | 平台自动托管（tools/ 挂载） |

> **压缩方式**：exe 用 **DEFLATE**；bat/platform 用 **STORE 平铺**（历史约定）。**exe 是 PublishSingleFile 单文件 framework-dependent**，从 v0.7.4 起发布产物只有 `Clipboard.exe` 一个文件（之前 v0.7.0-v0.7.3 是 5 文件：exe stub + dll + deps.json + runtimeconfig.json + pdb；只拷 exe 会加载旧 dll → "看着没改/没构建成功"，2026-09-08 血泪教训 v0.7.3）。安装目录约定：解压整个文件夹（含 `使用说明.txt` / `BUILD.txt` / `data/`），双击 `Clipboard.exe` 启动；不再需要保持 5 文件同目录同步。

## 三、平台版 zip 结构（约定）

```
clipboard-tool-v<版本>-platform.zip
└── clipboard/                    ← 解压后整个目录放服务器 tools/ 挂载目录
    ├── tool.json                 ← 平台接入声明（id/name/cmd/port/health/capabilities/dataFiles）
    ├── server.mjs
    ├── lib/  public/  scripts/
    ├── package.json  manifest.json
    └── 部署说明.md                ← 写清楚部署步骤（拷贝到 tools/ + 平台重扫 + 验证）
```

- **tool.json 字段规范**：`id`(kebab-case) / `name`(中文显示名) / `cmd`(启动命令) / `port`(工具端口) / `health`(健康检查路径) / `capabilities`(["storage" → 平台注入 CAP_STORAGE_DIR]) / `dataFiles`(数据文件声明,平台存储管理识别)
- zip 内一律**正斜杠路径**；压缩用 UTF-8（中文文件名）

## 四、发版流程（Checklist）

### 1. 前置验证
- [ ] 全量测试通过：冒烟 34 + WebDAV 集成 19 + merge 17 + html 10
- [ ] 副本实测可启动（health OK、版本指纹正确）
- [ ] `CHANGELOG.md` 已加版本节；`package.json version` 已同步

### 2. 打包
- [ ] 基于 `git archive HEAD` 构建（**只含已提交文件**，无 .data/.git/临时文件）
- [ ] 剔除开发中间产物（架构评估/优化计划/走查报告等，保留 README/CHANGELOG/DEVELOPMENT/AGENTS/docs）
- [ ] 各形态 zip 按上表命名，含对应说明文档

### 3. 发布（GitHub）
- [ ] `git tag v<版本>` + push（走代理 + 凭据）
- [ ] `gh release create v<版本> <zip资产> -t <版本> -n <notes>`（notes 含亮点/变更/运行要求/下载指引）
- [ ] 验证 release 资产可下载（API 查询 assets）

### 4. 部署（平台版）
- [ ] 解压 zip → `clipboard/` 目录拷贝到服务器 `tools/` 挂载目录
- [ ] 平台重扫（在线 API 或 `docker restart tools-center`）
- [ ] 验证：平台首页出现「剪贴板」、访问 `/tool/clipboard/`、健康检查通过、数据目录在 CAP_STORAGE_DIR

### 5. 发布后
- [ ] 更新 AGENTS.md 基线（日期 + 新 commit hash）
- [ ] 工作区干净、本地与远程一致（`git ls-remote` 核对）

## 五、回滚

- 代码回滚：`git revert` 或推送旧 tag
- 平台版回滚：服务器 `tools/clipboard/` 换回旧版本目录 + 重扫
- 数据安全：数据在 CAP_STORAGE_DIR（平台 data/ 挂载）与用户 WebDAV 双保险，代码回滚不丢数据
